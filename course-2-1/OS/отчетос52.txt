Отчёт по реализации и тестированию модели файловой системы
Краткое описание задачи
Целью данной работы является разработка модели файловой системы с базовыми командами для управления файлами. Реализованная файловая система должна поддерживать:

Иерархическую организацию (в виде дерева);
Команды для работы с файлами: создание, удаление, копирование, перемещение, запись и чтение;
Создание дампа файловой системы, отображающего её структуру и содержимое файлов;
Хранение файлов с использованием концепции блоков, где физическое представление файла — это список номеров блоков, в которых хранятся данные.
Кроме того, была проведена оценка производительности системы с помощью нагрузочного тестирования.

Описание методов, которые были использованы для решения задачи
1. Реализация иерархической структуры файловой системы

Иерархическая структура файловой системы была реализована с использованием следующих классов:

Directory — структура, представляющая директорию:

Содержит имя директории (name);
Карты (unordered_map) для хранения:
Поддиректорий (subdirectories);
Файлов (files).
FileSystem — основной класс, управляющий файловой системой:

Содержит корневую директорию (root) и указатель на текущую директорию (currentDirectory);
Реализует команды управления файлами и директориями.
2. Представление файлов и управление блоками

Файлы хранятся в виде:

Списка блоков: Каждый блок представляет собой единицу хранения фиксированного размера (например, 1 КБ);
Содержимого: Данные, записанные в файл, разбиваются на блоки.
Методы работы с блоками:

Выделение блока: Используется массив blockAvailability, который отслеживает свободные/занятые блоки. Первый свободный блок выделяется методом allocateBlock().
Освобождение блока: Метод releaseBlock() освобождает указанный блок после удаления или перезаписи файла.
3. Основные команды

Реализованы следующие команды:

Создание файла (createFile):

Проверяется наличие файла с таким именем в текущей директории.
Содержимое файла разбивается на блоки в соответствии с размером.
Каждый блок выделяется с использованием allocateBlock().
Удаление файла (deleteFile):

Проверяется существование файла в текущей директории.
Все блоки, занятые файлом, освобождаются методом releaseBlock().
Копирование файла (copyFile):

Создаётся новый файл с указанным именем, данные копируются в новые блоки.
Перемещение файла (moveFile):

Файл удаляется из текущей директории и добавляется в целевую директорию без изменения содержимого.
Чтение файла (readFile):

Выводится содержимое указанного файла.
Запись в файл (writeFile):

Содержимое перезаписывается, а использованные ранее блоки освобождаются.
Создание директории (createDirectory):

В текущей директории создаётся новая директория.
Смена директории (changeDirectory):

Реализована возможность навигации между директориями.
Вывод содержимого директории (listDirectory):

Отображаются файлы и поддиректории текущей директории.
4. Создание дампа файловой системы

Метод dumpFileSystem позволяет создать текстовый файл с дампом всей структуры. В дампе отображается:

Иерархия директорий;
Список файлов в каждой директории;
Номера блоков, в которых хранятся данные файлов;
Содержимое файлов.
Методы тестирования
Нагрузочное тестирование проводилось с целью оценки производительности программы при интенсивной работе. Тесты включали следующие сценарии:

Создание большого количества файлов:

Проверяет скорость выделения блоков и управления метаданными.
Создание глубокой иерархии директорий:

Оценивает время на создание и переход между вложенными директориями.
Запись и управление большими файлами:

Тестирует обработку больших данных (например, файла размером 1 МБ).
Графики нагрузочного тестирования
Сценарий 1: Создание большого количества файлов

Цель: Оценить скорость создания файлов.
Действия: Создаётся 1 000 файлов с уникальными именами и небольшим содержимым.
Результаты:
Зависимость времени от числа файлов линейная.
Узким местом является поиск свободного блока в массиве blockAvailability.
График 1:
(Пример данных: 100 файлов — 0.5 сек, 500 файлов — 2.5 сек, 1 000 файлов — 5.0 сек)

Сценарий 2: Глубокая иерархия директорий

Цель: Оценить производительность при работе с вложенными директориями.
Действия: Создаётся 100 вложенных директорий с переходами между ними.
Результаты:
Небольшое увеличение времени с увеличением глубины вложенности.
Сценарий 3: Запись большого файла

Цель: Проверить скорость записи большого файла.
Действия: Создаётся файл размером 1 МБ.
Результаты:
Линейная зависимость времени от размера файла.
Основное время тратится на выделение блоков.
Недостатки выявленные в тестах
Узкое место: Поиск свободного блока выполняется линейно. Это снижает производительность при большом количестве блоков.

Возможное улучшение: Использование структур данных (например, битового вектора).
Управление метаданными: С увеличением вложенности директорий возрастает время на обработку метаданных.

Фрагментация: Переходы между блоками при чтении большого файла могут замедлить работу.
