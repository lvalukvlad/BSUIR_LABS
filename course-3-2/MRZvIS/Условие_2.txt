Вторая лабораторная работа по моделям решения задач в интеллектуальных системах.
Тема: Программирование параллельного решения задач на параллельной архитектуре. 
Цель: реализовать и исследовать модель решения на ОКМД архитектуре задачи вычисления матрицы значений.
Задание по второй лабораторной работе по моделям решения задач в интеллектуальных системах.
Дано:
1. текст методического пособия по лабораторной работе; 
2. учебные материалы по программированию (материалы по javascript), основам организации и функционирования ЭВМ и другие;  
3. номер варианта задачи. 
Требуется:
1. построить модель ОКМД архитектуры, реализующей решение варианта задачи вычисления матрицы значений, обеспечивающую возможность параметрического задания времени счёта ti (длины) операций различных типов (сложение, разность, произведение, деление, сравнение и др.), удовлетворяющую нижеприведённым требованиям; наборы входных данных должны генерироваться;
2. построить семейства графиков эффективности, коэффициентов ускорения и расхождения, фиксируя n и r;
3. дать ответы на вопросы из списка;
4. предоставить письменный отчёт. 

Требования к реализации модели решения задачи на ОКМД архитектуре:
1. вычислить время последовательного (размер обрабатываемого в каждый момент времени вектора равен единице) решения задачи, время векторно-параллельного решения задачи (размер обрабатываемого в каждый момент времени вектора больше единицы), а также - среднее время (длину);
2. время вычислять в тактах в точном соответствии с количеством всех необходимых и достаточных для решения выполнений операции;
3. от реализации не требуется поддерживать физический параллелизм;
4. все операции унарные или бинарные, время выполнения каждой из них неизменно;
5. время выполнения арифметико-логической операции может быть только больше 0, время выполнения операции хранения (чтения и записи) полагается равным 0;
6. ранг основной задачи, число всех объектов (данных), которые можно обработать параллельно, включая хранимые в памяти, полагается неизменным, поэтому ранг операции записи результата полагается равным рангу чтения всех аргументов, то есть - сумме рангов чтения каждого из аргументов (ранг чтения и записи одних и тех же данных совпадает), ранги операции чтения входных данных одного типа полагаются равными (единице);
7. операции сравнения могут быть векторизированы, сведены к маскированию и выполнены без выполнения условных переходов;
8. для коэффициента ускорения времена работы параллельного и последовательного решения должны сравниваться на одном - и том же наборе данных (одной и той же индивидной задаче), аналогично для коэффициента расхождения; 
9. при переходе к задаче с иным рангом рекомендуется переходить от задачи с большим рангом к задаче с меньшим, не генерируя новых входных данных, сохраняя часть входных данных задачи с большим рангом;
10. во избежание переполнения генерацию входных данных рекомендуется осуществлять в диапазоне от -1 до 1.
