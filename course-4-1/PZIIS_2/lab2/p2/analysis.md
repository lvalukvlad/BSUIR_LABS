# Анализ по методике

Объект: то же приложение, что в части 1.

## Описание

Flask + SQLite, локальный HTTP. Заметки — открытый текст. Секреты — Fernet. Пароли — PBKDF2.

## Результаты

ОС: процесс без root; ключ и БД в instance с правами 600, каталог 700. Риск того же uid ОС остаётся высоким, если ключ лежит рядом с БД.

Компоненты: CSRF, ORM, изоляция по user_id, список секретов без расшифровки. Есть ограничение частоты входа. Заголовки секретов открыты. Ключ Fernet один на приложение.

Сеть: bind 127.0.0.1, HttpOnly, SameSite=Lax, CSP и nosniff. Без TLS cookie не Secure.

Конфиденциальность: тела секретов в SQLite — ciphertext; пароли — хэш. Компрометация fernet.key раскрывает все секреты.

Практика: чужой id даёт 404; POST без CSRF — 400; в БД заметка читается, секрет — hex BLOB.

## Меры

Per-user DEK, reverse-proxy с TLS, журнал доступа к секретам, ротация ключа, отдельный пользователь ОС.

## Использование

Не публиковать порт без TLS; не класть instance в публичный репозиторий; длинные пароли; после демонстрации ротировать ключ.
