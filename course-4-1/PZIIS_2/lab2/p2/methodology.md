# Методика оценки защищённости (часть 2)

Объект анализа: приложение **Secure Notes Lab** (результат лаб. №2.1).

## 1. Цель методики

Системно оценить защищённость сторонней (или собственной) программной системы по аспектам ОС, компонентов, сети и конфиденциальности данных; выявить риски и предложить меры улучшения.

## 2. Этапы оценки

1. **Инвентаризация** — состав компонентов (ОС, runtime, СУБД, веб-сервер, библиотеки, протоколы).
2. **Модель угроз** — активы (учётные данные, секреты, заметки, ключ шифрования), субъекты (пользователь, администратор ОС, сетевой злоумышленник), типовые атаки (брутфорс, SQLi, XSS, CSRF, MitM, доступ к файлам БД).
3. **Анализ ОС и окружения** — пользователь, от которого запущено приложение; права на файлы БД/ключа; обновления; firewall.
4. **Анализ компонентов и взаимодействий** — аутентификация, авторизация, CSRF, шифрование, хранение паролей, границы доверия между UI и БД.
5. **Сетевая политика** — интерфейс прослушивания, TLS, cookie flags.
6. **Конфиденциальность данных** — что считается секретом; шифрование at-rest; изоляция по пользователям; ключи.
7. **Организационные меры** — кто администрирует, бэкапы, ротация ключей, политика паролей.
8. **Практическая проверка** — сценарии: регистрация/вход/CRUD/поиск/выход; попытка доступа к чужим id; проверка CSRF; осмотр БД на диске.
9. **Выводы и рекомендации** — список рисков (критичность), меры усовершенствования, правила безопасного использования.

## 3. Критерии

| Уровень | Описание |
|---------|----------|
| Высокий | Уязвимость эксплуатируется без привилегий / даёт полный доступ к секретам |
| Средний | Требует частичного доступа или локального присутствия |
| Низкий | Смягчается конфигурацией / маловероятна в учебном контуре |
